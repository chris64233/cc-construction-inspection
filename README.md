# cc-construction-inspection

建设许可、施工阶段与检查资料管理服务。

实现建设许可按施工阶段完成检查、整改和最终使用批准的全流程管理。

## 开发环境

- JDK 21
- Maven Wrapper 3.9.9
- Spring Boot 4.1.1

迁移项目沿用现有 Spring Boot 版本，其他项目使用上述版本。

## 主要业务规则

1. **许可与阶段定义**：创建许可时按顺序定义施工阶段，每个阶段定义所需检查项。
   第一个阶段激活（ACTIVE）并生成初始工程版本 v1，其余阶段为 PENDING。
   许可创建时生成初始方案版本 v1（`currentPlanVersion`）。
2. **检查记录**：每条检查记录包含结论（PASS/FAIL）、检查人、证据和被检查的工程版本。
   只有前置阶段全部验收完成、当前阶段处于 ACTIVE 时，才能提交该阶段的检查。
   提交必须携带所基于的方案版本（planVersion）与工程版本（stageVersion），
   与当前版本不一致时拒绝过期提交。
3. **整改与复检版本**：结论不通过的检查自动生成整改项（OPEN）；整改提交后整改项关闭，
   并为阶段产生新的复检版本（v2、v3…），形成"不通过记录 → 整改项 → 新版本"的整改链。
4. **阶段一次性验收**：只有当前（最新）工程版本上所有检查项都通过、且阶段内整改项全部关闭，
   阶段才能验收完成；验收通过后自动激活下一阶段（仅当下一阶段为 PENDING）。
   验收读取的是最新版本，旧版本上的通过结论不构成验收依据（不基于过期结果）。
5. **幂等与唯一结论**：检查提交号（submissionNo）全局唯一，重复提交返回首次记录；
   同一检查项在同一工程版本上只允许一条生效结论（数据库唯一约束兜底）。
6. **方案变更**：对已生效许可登记变更单并标明受影响阶段。变更批准后：
   - 生成新方案版本（v2、v3…），与变更单关联；
   - 受影响阶段产生 AMENDMENT 原因的新工程版本并回到 ACTIVE，旧版本上的检查结果
     保留为历史但不再构成验收依据，未关闭的整改项随旧方案作废，
     失效阶段必须按新方案版本重新检查、重新验收；
   - 未受影响阶段的状态与有效检查结果完整保留，不产生新版本；
   - 尚未激活（PENDING）的受影响阶段无结果可失效，后续激活时初始版本归属新方案版本。
   许可已最终批准后不可再发起或批准变更。
7. **并发一致性**：检查提交、整改关闭、阶段验收与变更批准共用阶段行级悲观锁；
   最终批准、停工令签发与变更批准共用许可行级悲观锁。
   变更批准、检查提交、整改提交与最终批准均携带期望方案版本号，
   并发导致方案版本前进后，基于旧版本的过期操作一律拒绝（409）。
8. **最终使用批准**：要求全部阶段验收完成、不存在活动停工令，
   且请求的方案版本等于当前方案版本——批准只能引用当前方案和有效结果。
   批准记录（含方案版本号与各阶段验收版本快照）一经形成不可修改：
   不可重复批准，批准后不可再签发停工令、不可再变更。
9. **关联完整性**：方案版本 → 工程版本 → 检查记录/整改链 → 最终批准依据完整关联；
   变更批准涉及的新方案版本、失效阶段版本、作废整改项在同一事务内更新，
   要么全部生效要么全部回滚。

## 主要接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/api/permits` | 创建许可（含阶段与检查项定义） |
| GET | `/api/permits/{id}/stages` | 许可阶段查询 |
| POST | `/api/inspections` | 提交检查结论（幂等提交号 + 方案/工程版本号） |
| POST | `/api/rectifications/{id}/submit` | 整改提交（关闭整改项并产生复检版本） |
| POST | `/api/stages/{id}/accept` | 阶段一次性验收 |
| GET | `/api/stages/{id}/versions` | 检查版本查询（含各版本检查记录与所属方案版本） |
| GET | `/api/stages/{id}/rectifications` | 整改链查询 |
| POST | `/api/permits/{id}/amendments` | 登记方案变更（标明受影响阶段） |
| POST | `/api/amendments/{id}/approve` | 批准变更（生成新方案版本，受影响阶段结果失效） |
| GET | `/api/permits/{id}/amendments` | 变更单查询 |
| GET | `/api/permits/{id}/plan-versions` | 方案版本查询 |
| POST | `/api/permits/{id}/stop-work-orders` | 签发停工令 |
| POST | `/api/stop-work-orders/{id}/lift` | 解除停工令 |
| POST | `/api/permits/{id}/final-approval` | 最终使用批准（须携带当前方案版本号） |
| GET | `/api/permits/{id}/final-approval` | 最终批准依据查询（批准快照 + 各阶段验收版本 + 停工令历史） |

业务规则冲突返回 409，资源不存在返回 404，参数不合法返回 400。

## 常用命令

运行测试：

    ./mvnw clean test

启动服务：

    ./mvnw spring-boot:run
